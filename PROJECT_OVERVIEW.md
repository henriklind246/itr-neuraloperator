# Project Overview: Time-Conditioned 2D FNO for Transient Multilayer Heat Conduction

## 1. Current Scope

This project trains a forward surrogate for transient 2D heat conduction in a
two-layer material with interfacial thermal contact resistance. The primary
surrogate is a time-conditioned 2D Fourier Neural Operator (FNO) trained on
trajectories generated by a conservative finite-volume Crank-Nicolson solver.

The active task is:

```text
given T(x, y, t_s), geometry/coordinate features, forcing/contact conditioning
predict T(x, y, t_j), where t_j > t_s
```

The 1D solver/FNO/MMS files remain as a tested baseline, but the active target
is the 2D pipeline.

Current high-level state:

| Area | Current state |
|------|---------------|
| Physics | 2D transient heat equation on `[0, 1] x [0, 1]` |
| Materials | Two fixed vertical slabs, interface at `x = 0.5` |
| Varying material/contact parameter | `R_c in [0.05, 1.0]` |
| Left boundary forcing | Separable heat flux `q_L(y, t) = a(t) * s(y)`, with a temporal forcing function and a spatial profile function |
| Temporal forcing families | `sin`, `exp`, `pulse_train`, `exp_train` |
| Spatial forcing families | `uniform`, `patch`, `gaussian`, `triangle` |
| Dataset target | 8000 simulations in current config/main generation path |
| Model input | 8 spatial channels plus 28D conditioning vector |
| Current empirical issue | Cross-simulation validation remains much higher than train |

## 2. Governing Physics

The PDE is the transient 2D heat equation with piecewise-constant material
properties:

```text
rho(x) * cp(x) * dT/dt = div(k(x) * grad T)
```

The dataset uses no volumetric source term. Heating enters through the left
boundary flux.

Domain and materials:

| Region | Properties |
|--------|------------|
| `x in [0, 0.5]` | `k = 2`, `rho = 1`, `cp = 1` |
| `x in [0.5, 1]` | `k = 1`, `rho = 1`, `cp = 1` |

Boundary conditions:

| Boundary | Condition |
|----------|-----------|
| Left, `x = 0` | Neumann flux `q_L(y, t) = a(t) * s(y)` |
| Right, `x = 1` | Dirichlet `T = 300 K` |
| Bottom/top, `y = 0, 1` | Adiabatic |

Interface condition at `x = 0.5`:

```text
q_left = q_right
Delta T = R_c * q_interface
```

The contact resistance `R_c` is sampled per simulation. The layer material
properties are fixed in the current dataset.

## 3. Boundary Forcing

**File**: `src/physics/boundary_forcing.py`

The left boundary heat flux is represented as the product of two independently
sampled functions: a temporal forcing function `a(t)` and a spatial profile
function `s(y)`:

```text
q_L(y, t) = a(t) * s(y)
```

The temporal function controls when and how strongly heat is injected. The
spatial profile controls where along the left boundary that heat is applied.
Each simulation stores both choices explicitly in `sim_params.npy` as
`temporal_family` / `temporal_params` and `spatial_family` /
`spatial_params`.

### Temporal Families

| Family | Meaning |
|--------|---------|
| `sin` | Windowed sinusoid on `[t_on, t_off] = [0, 0.2]` |
| `exp` | Single exponential pulse beginning at `t0` |
| `pulse_train` | Sum of rectangular pulses |
| `exp_train` | Sum of exponential pulses |

Temporal parameter ranges are defined in `boundary_forcing.py`. Amplitudes use
`[50, 300]`. Frequencies and time constants are sampled in log-sensitive ways
where appropriate.

### Spatial Families

| Family | Meaning |
|--------|---------|
| `uniform` | Full left edge |
| `patch` | Rectangular band in `y` |
| `gaussian` | Gaussian profile in `y` |
| `triangle` | Compact triangular profile in `y` |

Each spatial profile is normalized so its maximum is 1.

### Future-Forcing Bin Channels

The dataset computes `FORCING_BINS = 4` temporal integrals over equal
sub-intervals of `[t_s, t_j]`:

```text
Q_bin_k(y) = s(y) * integral_bin_k a(t) dt
```

These four fields are normalized by:

```text
Q_REF = SIN_AMP_RANGE[1] * t_final / FORCING_BINS
```

and appended as spatial channels. This gives the FNO direct access to both
how much heat is injected and roughly when it is injected within the prediction
window.

## 4. Finite-Volume Solver

**File**: `src/physics/fv_solver_2d.py`

The 2D solver is a conservative Crank-Nicolson finite-volume method on a
uniform isotropic grid.

Key implementation facts:

| Feature | Current behavior |
|---------|------------------|
| Grid | Uniform, isotropic, `hx == hy` |
| Geometry | Rectangular domain |
| Layers | Vertical slabs only |
| Interfaces | Must lie on x-direction cell faces |
| Time stepping | Crank-Nicolson |
| Matrix | Sparse 5-point stencil, factored once via `splu` |
| Left BC | Half-cell FV Neumann energy balance |
| Right BC | Dirichlet identity row |
| Top/bottom BC | Adiabatic half-cell control volumes |

The solver accepts a left-flux callable. For this project, data generation
passes a separable `q_left_fn(t)` that returns a `(Ny,)` vector.

## 5. MMS Verification

**Primary file**: `src/physics/mms_2d.py`

The solver is verified with manufactured solutions that cover:

| Case | Purpose |
|------|---------|
| y-independent solution | Confirms 2D solver recovers 1D-like behavior |
| Full 2D solution | Exercises y diffusion and adiabatic top/bottom boundaries |
| Interface with `R_c` | Tests jump condition and flux continuity |
| Off-center interface | Tests interface placement away from midpoint |

Numerical-scheme changes require MMS verification before being considered
correct.

## 6. Data Generation

**File**: `data/generate_dataset.py`

Current generation settings:

| Setting | Value |
|---------|-------|
| Domain | `[0, 1] x [0, 1]` |
| Grid | `Nx = Ny = 100` |
| Solver `dt` | `0.005` |
| `t_final` | `0.3` |
| Save stride | `2` |
| Saved snapshots | `31` |
| Current generated target | 8000 simulations |
| Split | 70/15/15 by simulation ID |

`generate_sim_data` defaults to 2000 sims when called directly, but the current
`__main__` path and `conf/config.yaml` target 8000 simulations.

### Sampling

`R_c` is sampled by 1D Latin Hypercube Sampling over `[0.05, 1.0]`.

Temporal and spatial forcing families are sampled per simulation by the
registries in `boundary_forcing.py`:

```text
TEMPORAL_SAMPLERS
SPATIAL_SAMPLERS
```

The saved `sim_params.npy` schema is:

```text
{
  "R_c": float,
  "T0": np.ndarray shape (Nx, Ny),
  "temporal_family": str,
  "temporal_params": dict,
  "spatial_family": str,
  "spatial_params": dict,
}
```

### Initial Conditions

Each simulation uses a smooth, separable, y-varying initial condition:

```text
T0(x, y) = random smooth fx(x) * random smooth fy(y) + 300
```

The right Dirichlet edge is pinned to 300 K in the initial condition to avoid a
spurious initial discontinuity at `x = 1`.

### Output Files

| File | Shape / contents |
|------|------------------|
| `trajectories.npy` | `(num_sims, 31, 100, 100)` |
| `x_grid.npy` | `(100,)` |
| `y_grid.npy` | `(100,)` |
| `t_grid.npy` | `(31,)` saved snapshot times |
| `dt.npy` | scalar solver dt, required by dataset encoding |
| `sim_params.npy` | object array with per-simulation metadata |

`dt.npy` is important because saved snapshot spacing is not the solver time
step when `save_stride > 1`.

## 7. Dataset and Pair Construction

**File**: `data/dataset.py`

`SnapshotPairDataset` builds all forward-in-time pairs from a subsampled set of
time snapshots. Pairs are sorted by lead time so the training loop can expose
longer horizons gradually through curriculum learning.

Current config:

| Setting | Value |
|---------|-------|
| Training snapshots per sim | `n_snapshots = 14` |
| Test snapshots per sim | `n_snapshots_test = 40` |
| Pairs per training sim | `C(14, 2) = 91` |
| 8000-sim split | 5600 train, 1200 val, 1200 test |
| Training pairs at full curriculum | 509,600 |
| Validation pairs per validation pass | 109,200 |

### Per-Sample Output

Each dataset item returns:

| Tensor | Shape | Description |
|--------|-------|-------------|
| `spatial` | `(Nx, Ny, 8)` | Spatial channels |
| `cond` | `(28,)` | Conditioning vector |
| `Y` | `(Nx, Ny, 1)` | Target normalized temperature |
| `T_stats` | `(2,)` | `[mu_global, sigma_global]` |

Spatial channel layout:

```text
0: T_tilde_source
1: x_norm
2: y_norm
3: s_y
4: Q_y_bin_0
5: Q_y_bin_1
6: Q_y_bin_2
7: Q_y_bin_3
```

`s_y` and the four `Q_y_bin_k` channels are y-only profiles broadcast across x
so the model sees the spatial forcing footprint and the per-bin heat-injection
totals as full 2D fields.

### Conditioning Vector

`COND_DIM = 28`. Layout:

```text
[0:3]    base: t_bar_norm, t_s_norm, R_c_norm
[3:7]    spatial onehot: uniform, patch, gaussian, triangle
[7:11]   spatial params: y_c, w, sigma_y, ell
[11:15]  temporal onehot: sin, exp, pulse_train, exp_train
[15:28]  temporal params: 1 scalar slot + 4 pulse slots x 3 values
```

Use `build_cond_vector(...)` whenever constructing conditioning vectors outside
`SnapshotPairDataset`; do not duplicate slot logic.

### Normalization

Temperature fields use global normalization:

```text
T_tilde = (T - mu_global) / (sigma_global + 1e-6)
```

`mu_global` and `sigma_global` are computed from the training simulations only.
The project deliberately does not use per-sample normalization.

### Same-Sim Held-Out Pair Diagnostic

`split_pairs_within_sims(dataset, val_pair_frac=0.1, seed=0)` creates train and
validation datasets that share the same simulation IDs but use disjoint
snapshot-pair lists. The script `scripts/eval_same_sim_holdout.py` runs this
diagnostic through the standard training path.

Interpretation:

| Result | Meaning |
|--------|---------|
| same-sim val much lower than cross-sim val | overfitting is mostly simulation-level |
| same-sim val similar to cross-sim val | representation/optimization issue is more likely |

## 8. FNO2d Model

**File**: `src/operators/fno2d.py`

The model forward signature is:

```text
model(spatial, cond) -> y_pred
```

with:

```text
spatial: (B, Nx, Ny, 8)
cond:    (B, 28)
y_pred:  (B, Nx, Ny, 1)
```

Default config:

| Parameter | Value |
|-----------|-------|
| `modes1` | 16 |
| `modes2` | 16 |
| `width` | 64 |
| `n_layers` | 4 |
| `in_channels` | 8 |
| `cond_dim` | 28 |
| `cond_hidden` | 256 |
| `dropout` | 0.0 |
| `spectral_dropout` | 0.0 |

### Architecture

| Stage | Operation |
|-------|-----------|
| Lift | `Linear(8, width)` on channels-last spatial input |
| Permute | Convert to `(B, width, Nx, Ny)` |
| Pad | Zero-pad x and y by 8 on the high side |
| Fourier blocks | `SpectralConv2d + 1x1 Conv2d + CIN + GELU + dropout` |
| Unpad | Crop back to physical `(Nx, Ny)` |
| Project | `Linear(width, 128) + GELU + Linear(128, 1)` |

### SpectralConv2d

`SpectralConv2d` uses `torch.fft.rfft2`, keeps `modes1` in x and `modes2` in
y, applies learned complex channel mixing to positive and negative x-mode
slices, and returns to physical space with `irfft2`.

The implementation raises if `2 * modes1 > Nx_freq`, because positive and
negative x-mode slices would overlap.

### Conditional Instance Normalization

Each Fourier block uses native `nn.InstanceNorm2d(affine=False)` followed by
conditioning-dependent affine parameters:

```text
CIN(x) = gamma[:, :, None, None] * InstanceNorm2d(x) + beta[:, :, None, None]
```

The normalization is currently over the full padded tensor. A padding-aware
manual CIN variant was tested, but current code is back to native PyTorch
`InstanceNorm2d` because it is faster, lower memory, and empirically behaved
better in training.

### ConditioningMLP

The 28D conditioning vector is mapped to per-layer `(gamma, beta)`:

```text
Linear(28, cond_hidden) -> SiLU
Linear(cond_hidden, cond_hidden) -> SiLU
Linear(cond_hidden, n_layers * 2 * width)
```

The final head is identity-initialized so the model starts as an unconditioned
FNO (`gamma = 1`, `beta = 0`).

## 9. Losses and Metrics

**File**: `src/operators/losses.py`

Training loss is `SpatiallyWeightedMSE` in normalized temperature space:

```text
mean(w(x, y) * (y_pred - y_true)^2)
```

The interface slab is upweighted using:

| Config key | Default |
|------------|---------|
| `interface_x` | `0.5` |
| `interface_half_width` | `0.05` |
| `interface_weight` | `10.0` |

Weights are normalized to mean 1 so the loss scale remains comparable.

### Metrics

Training and validation metrics use normalized-space relative RMS error:

```text
sqrt(mean((pred - true)^2) / mean(true^2)) * 100
```

`train_metrics.csv` logs aggregate train/validation metrics. `val_pairs.csv`
logs per-pair diagnostics with the same normalized-space metric definition.

`eval.py` computes final test metrics in physical temperature space after
denormalization. Training/validation metrics and test metrics are therefore
not directly interchangeable.

### Per-Pair Validation CSV

When validation runs, `train.py` appends one row per validation pair:

```text
epoch, sim_id, temporal_family, spatial_family, t_s, t_bar, R_c,
rel_l2, iface_rel_l2
```

This file is intended for offline grouping by family, lead time, contact
resistance, and simulation ID.

## 10. Training Pipeline

**File**: `src/operators/train.py`

The main per-seed entry point is `run_one_seed(...)`.

Pipeline:

1. Load trajectories, grids, `sim_params`, and solver `dt`.
2. Split simulations 70/15/15 using fixed split seed 0.
3. Compute global temperature stats from training simulations only.
4. Build train/val/test dataloaders.
5. Construct `FNO2d` from config.
6. Train with curriculum over lead time.
7. Validate every `validate_every` epochs.
8. Save `fno2d_best.pt` when validation improves.
9. Save `fno2d_latest.pt` every epoch for resume.
10. Delete `fno2d_latest.pt` on clean completion.

### Per-Run Artifacts

`run_one_seed` writes the following alongside the checkpoints so each run is
self-describing for later experiment auditing:

| File | Contents |
|------|----------|
| `git_commit.txt` | Full + short HEAD SHA at run start |
| `git_status.txt` | `git status --short` at run start |
| `slurm_job.txt` | SLURM env (job id, node), hostname, argv, start UTC |
| `config_used.yaml` | Resolved Hydra/OmegaConf config actually used |
| `train_metrics.csv` | Aggregate per-epoch metrics |
| `val_pairs.csv` | Per-validation-pair diagnostics |
| `final_metrics.json` | Best/final epoch summary, wall time, status, model/training params, git short SHA |
| `fno2d_best.pt` | Best-validation checkpoint |
| `fno2d_latest.pt` | Resume checkpoint (deleted on clean completion) |

Current training defaults:

| Setting | Value |
|---------|-------|
| Optimizer | AdamW |
| Peak LR | `0.002` |
| Weight decay | `1e-5` |
| Batch size | `1024` |
| Gradient clipping | `1.0` |
| Validate every | 10 epochs |
| Patience | 20 validation checks |
| Curriculum warmup | 35 epochs |

### Scheduler

The default scheduler is `RIGNOThreePhase`:

| Phase | Fraction | Behavior |
|-------|----------|----------|
| Warmup | 0.02 | ramp from `0.05 * peak_lr` to `peak_lr` |
| Cosine | 0.88 | decay to `0.05 * peak_lr` |
| Exponential | 0.10 | decay to `0.005 * peak_lr` |

The configured `training.learning_rate` is the peak LR.

### Fixed-Config Script

`scripts/run_train_fixed.py` loads `conf/config.yaml`, applies dotted
`key=value` overrides, resolves the run directory from
`experiment.name/config_id`, and calls `run_config_seeds`.

Example:

```bash
python scripts/run_train_fixed.py \
  experiment.name=E5b_101ep \
  config_id=0 \
  training.epochs=101 \
  training.seeds=[42] \
  training.batch_size=1024
```

## 11. Evaluation

**File**: `src/operators/eval.py`

Evaluation:

1. Finds `seed*/fno2d_best.pt` checkpoints.
2. Rebuilds the FNO from checkpoint config.
3. Builds a test dataloader using `n_snapshots_test`.
4. Denormalizes predictions and targets.
5. Reports physical-space `test_rel_l2` and `test_iface_rel_l2`.
6. Writes `seed_report.json`.

The eval code expects the current 8-channel model input. Old 4-channel
checkpoints are intentionally incompatible.

## 13. Current Empirical Status

The main remaining issue is cross-simulation generalization. Same-simulation
held-out-pair experiments showed much smaller gaps than cross-simulation
validation, which suggests the FNO can interpolate within seen trajectories but
struggles to generalize to unseen simulation parameter/forcing combinations.

Recent per-pair diagnostics repeatedly show that validation error is not
uniformly distributed:

| Hard regime | Observation |
|-------------|-------------|
| `pulse_train` temporal forcing | Consistently highest temporal-family error |
| `exp_train` | Often second hardest |
| Long lead times | Error rises strongly with `t_j - t_s` |
| Spatial family | `uniform` and `patch` can both be hard; not only one spatial family |
| `R_c` | Weaker error driver than temporal family and lead time |

Current likely next interventions:

1. Rerun clean `InstanceNorm2d` baseline for any experiment that used the
   padding-aware CIN variant.
2. Add lead-time-balanced sampling or weighting.
3. Add hard-regime sampling/weighting for `pulse_train` and `exp_train`.
4. Consider increasing `FORCING_BINS` from 4 to 8 for sharper pulse timing.
5. If generating more data, prefer targeted hard-regime simulations over
   uniform brute-force expansion.

## 15. Design Decisions

| Decision | Rationale |
|----------|-----------|
| Split by simulation ID | Prevents leakage between correlated pairs from the same trajectory |
| Global temperature normalization | Preserves absolute thermal scale |
| 28D condition vector | Encodes family identity and normalized family parameters |
| `s_y` as spatial channel | Gives the model direct access to the forcing spatial profile |
| Future-forcing bins | Gives the model a functional summary of heat injected between `t_s` and `t_j` |
| CIN for conditioning | Modulates hidden features using the conditioning vector |
| Native `InstanceNorm2d` | Fast, memory-efficient, and currently empirically preferred |
| Curriculum by lead time | Stabilizes learning by starting with shorter horizons |
| Interface-weighted MSE | Emphasizes the physical temperature jump near `x = 0.5` |
| Fixed material properties | Current operator varies forcing and `R_c`, not material coefficients |
| `dt.npy` required | Snapshot cadence differs from solver dt because of save stride |
